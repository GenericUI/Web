# `:web` — Browser Backend (`jsMain` & `wasmJsMain` — Bootstrap 5 + DOM)

## Overview
`:web` is the browser backend for GenericUI, targeting both **Kotlin/Wasm** (`wasmJs`, primary default) and **Kotlin/JS IR** (`js`, automatic fallback). It renders native HTML5 DOM elements (`WebDomElement`) styled with Bootstrap 5.3 (`bootstrap.min.css`, `bootstrap-icons.css`) and depends on `:common` and `:systemCommon`.

---

## Single-`commonMain` Architecture & `WebLauncher`

Consumer applications write their UI and `@MainAppFragment` / `@AppFragment` classes strictly in `src/commonMain/kotlin` and `src/commonMain/resources`. The GenericUI Gradle plugin (`GenericUiGenerateLaunchersTask`) automatically generates the `jsMain` and `wasmJsMain` launcher stubs calling `WebLauncher`:

```kotlin
// Auto-generated by GenericUiGenerateLaunchersTask in build/generated/genericui/launchers/{jsMain,wasmJsMain}
fun main() {
    WebLauncher.launch(
        title = "My App",
        width = 1280,
        height = 800,
        mainFragmentFactory = { MyMainFragment() }
    )
}
```

When `styles { globalStyleSheet = "styles/main.scss" }` is configured in `build.gradle.kts`, the generated startup code automatically calls `app.addStyleSheet("styles/main.scss")`, which `WebStyleSheetManager` normalizes to `"styles/main.css"` and injects as `<link rel="stylesheet" href="styles/main.css">` in `document.head`. When `genericui { theme { ... } }` is configured in `build.gradle.kts`, the generated launcher also initializes `app.setThemeConfig(ThemeConfig(...))` at startup and `GenericUiWebDistributionTask` emits a build-time pre-generated `gui/genericui-theme.css` linked via `<link id="genericui-build-theme-css" rel="stylesheet" href="./gui/genericui-theme.css">` in `index.html`.

## `WebDomElement` User CSS Class Isolation, `WebCssStyleTranslator`, `ComponentBootstrap`, `ComponentStyle`, & Custom Cursors

1. **Strict Separation of `userClassList` and `enumClassList` (`WebDomElement`)**:
   - `WebDomElement` maintains two separate class sets:
     - `userClassList`: Mutated and returned **exclusively** by `addClass`, `removeClass`, `hasClass`, `getClasses()`, `getClass()`, `setClass`, and `WebDomElement.className`.
     - `enumClassList` (`setEnumClasses`): Populated internally from `ComponentBootstrap` (`component.getBootstrap()` — e.g., `BootstrapType`, `BootstrapSize`, `BootstrapWidth`, `SpacingScale`, `FlexDirection`, `FlexWrap`), remaining **100% invisible** to `getClasses()` and `hasClass()`.
   - `WebDomElement.getEffectiveDomClassName()` merges `enumClassList + userClassList` **only** when syncing the underlying browser DOM element's `class` attribute (`WebBrowserDomBridge.syncClassName`).
2. **`BootstrapType.NONE` Default**:
   - When `component.getBootstrap().type == BootstrapType.NONE` (`BootstrapType.None`, the default), no semantic `btn-*` color variant class is added unless a semantic `BootstrapType` (`PRIMARY`, `DANGER`, `SUCCESS`, `WARNING`, `INFO`, `SECONDARY`, `LIGHT`, `DARK`, `LINK`) is explicitly set.
3. **Strongly-Typed `ComponentStyle` (`getStyle()`) & `WebCssStyleTranslator` (No String-Keyed Style APIs in `:common`)**:
   - GenericUI does **not** expose string-keyed style APIs (`setStyleProperty(String, String)` is prohibited in `:common`), enabling non-web system backends to evaluate styles via typed fields and 128-bit `CssProperty` bitmasks (`importantMaskLo` / `importantMaskHi`) with zero string formatting or `Map<String, String>` allocation.
   - On `:web`, `WebCssStyleTranslator` translates strongly-typed `ComponentStyle` and `ComponentBootstrap` properties directly into DOM CSS declarations via `WebDomElement.setStyle(property, value, important)` (and `WebBrowserDomBridge.syncStyle` / `element.style.setProperty(prop, value, "important")`), including standard CSS `accent-color` (`setAccentColor`) and explicit `top` / `right` / `bottom` / `left` positioning properties.
   - Because inline HTML `element.style` does not support pseudo-classes (`:hover`, `:focus`, `:active`), `ComponentStyle` has zero pseudo-state subblocks; hover/focus/active rules are authored in `.scss` stylesheets compiled by `GenericUiSassCompileTask`.
4. **Custom Cursors (`CssCustomCursor`)**:
   - Setting a `CssCustomCursor` (PNG `ResourceID`, SVG `ResourceID`/markup, or `ImageBuffer` with `hotspotX`, `hotspotY`, and `fallback`) emits standard CSS `cursor: url("assets/drawable/<name>.png") <hotspotX> <hotspotY>, <fallback>` onto `WebDomElement.style["cursor"]`.

## Dynamic `<link rel="stylesheet">` Management (`WebStyleSheetManager`), `ThemeMode.AUTO`, & Pre-Generated + Runtime `ThemeConfig` CSS

- **`IApplication.addStyleSheet` / `removeStyleSheet` (`WebStyleSheetManager`)**:
  - `.scss` files in `src/commonMain/resources/**` are compiled at build time into `.css` files in the Web distribution (`GenericUiSassCompileTask`).
  - Calling `app.addStyleSheet(R.style.main)` or `app.addStyleSheet("styles/main.scss")` resolves the compiled `.css` path (`"styles/main.css"`) and inserts `<link id="genericui-stylesheet-styles-main-css" rel="stylesheet" href="styles/main.css">` into `document.head`.
  - Calling `app.removeStyleSheet(...)` removes the corresponding `<link>` element from `document.head`.
- **`IApplication` Theming (`ThemeMode.AUTO`, `DARK`, `LIGHT` — Default `AUTO`)**:
  - Defaults to **`ThemeMode.AUTO`**, querying `window.matchMedia("(prefers-color-scheme: dark)").matches` and listening for live OS color-scheme `change` events.
  - Synchronizes `document.documentElement.setAttribute("data-bs-theme", "light" | "dark")` so Bootstrap 5.3 light/dark color modes update immediately across the entire DOM.
- **Cross-Platform `ThemeConfig` & `ThemeColorSet` (Build-Time `gui/genericui-theme.css` + Runtime `<style id="genericui-runtime-theme-css">`)**:
  1. **Build-Time Pre-Generated `gui/genericui-theme.css` (`<link id="genericui-build-theme-css">`)**:
     - During `packageGenericUiWebDistribution`, `GenericUiWebDistributionTask` generates `gui/genericui-theme.css` from the `genericui { theme { ... } }` configuration in `build.gradle.kts` (`primaryColor`, `secondaryColor`, `accentColor`, `successColor`, `dangerColor`, `warningColor`, `infoColor`, `lightColor`, `darkColor`, `backgroundColor`, `surfaceColor`, `textPrimaryColor`, `textSecondaryColor`, `borderColor`, plus `light { ... }` and `dark { ... }` mode overrides) and links it in `index.html` via `<link id="genericui-build-theme-css" rel="stylesheet" href="./gui/genericui-theme.css">`.
     - Emits `:root, [data-bs-theme="light"]` and `[data-bs-theme="dark"]` CSS custom property blocks (`--bs-primary`, `--bs-primary-rgb`, `--bs-secondary`, `--bs-success`, `--bs-danger`, `--bs-warning`, `--bs-info`, `--bs-light`, `--bs-dark`, `--bs-body-bg`, `--bs-body-color`, `--bs-border-color`, `--genericui-accent`, `--genericui-surface-bg`, `--genericui-text-secondary`) together with `.btn-*`, `.btn-outline-*`, `.text-bg-*`, `.bg-*`, `.text-*`, and `.border-*` overrides so initial page paint has zero Flash of Unstyled Content (FOUC).
  2. **Runtime `<style id="genericui-runtime-theme-css">` Injection (`WebStyleSheetManager.applyThemeConfig`)**:
     - Calling `app.setThemeConfig(config)` or `app.setThemeColor(argb)` at runtime updates `BootstrapColorPalette.activeConfig` and invokes `WebStyleSheetManager.applyThemeConfig(config, resolvedMode)`, which dynamically injects or updates `<style id="genericui-runtime-theme-css">` in `document.head` (placed after `<link id="genericui-build-theme-css">`) and synchronizes `<meta name="theme-color">`.

## Browser `#hash` & `window.history.state` Integration (`WebFragmentHistoryBridge`)

`WebFragmentHistoryBridge` binds `FragmentHostFragment` to the browser's HTML5 History API (`window.location.hash` and `window.history.state`), pushing `#<fragmentId>` URL hashes and serializing `args: FragmentBundle` and `onSaveState(outState)` into `window.history.state` for full browser Back/Forward (`popstate`) restoration.

## Web `TitleCapabilities` & 4-State Navbar / MenuBar Chrome Rules

`WebWindowImpl` reports `TitleCapabilities(isTitleBarRequired = false, isEmulated = true, titleBarRendersAsNavbar = true, menuBarRendersAsNavbar = false, menuBarMergesIntoTitleNavbar = true)`:
1. **Neither `TitleBar` nor `MenuBar` set**: Zero top chrome; root container fills `100vw x 100vh`.
2. **`MenuBar` only**: Renders a horizontal Bootstrap menu bar (`<nav class="genericui-menubar">`).
3. **`TitleBar` only**: Renders a Bootstrap `<nav class="navbar navbar-expand ...">` (`WebNavbarImpl`) with single-placement custom components (`mountedInTitleBar = true`).
4. **Both `TitleBar` and `MenuBar` set**: Merges both into a single Bootstrap `<nav class="navbar">`.

## Bare-Metal Browser Async I/O, `IFileSystem`, `PreferenceStore` (`window.localStorage`), `window.indexedDB` (`UserDirectory` vs. `Database`), & Networking

### 1. `PreferenceStore` (`WebPreferenceStoreImpl` — `window.localStorage` with `"genericui:"` Key Prefix)
- **`WebPreferenceStoreImpl`**: Backed by browser **`window.localStorage`** and `window.addEventListener("storage", ...)` cross-tab change notifications.
- **`"genericui:"` Key Prefix (`genericui:<key>`)**: Every preference key is stored in `window.localStorage` under the **`"genericui:"`** prefix (`genericui:<key>`, e.g., `localStorage.getItem("genericui:$key")` / `localStorage.setItem("genericui:$key", json)`), while `keys()` strips the `"genericui:"` prefix and ignores non-prefixed keys. This prevents collisions with third-party JavaScript libraries, analytics scripts, plugins, and browser addons sharing the page's `window.localStorage` origin.

### 2. Async `Readable`, `Writable`, `ByteBuffer`, `IFileSystem`, & `FileSystemAvailability`
- **`FileSystemAvailability`**:
  - **`FileSystem.isAvailable()` returns `FileSystemAvailability.WithPermission`**: Direct local file and directory access in the browser uses the **File System Access API** (`window.showOpenFilePicker`, `window.showSaveFilePicker`, `window.showDirectoryPicker`, `FileSystemFileHandle`, `FileSystemDirectoryHandle`, and `FileSystemWritableFileStream`) with automatic fallback to `<input type="file">` and `<a download>` when picker handles are unavailable.
  - **`UserDirectory.isAvailable()` (`ConfigDirectory` & `CacheDirectory`) returns `FileSystemAvailability.Always`**: Browser-persisted application config and cache directories require zero user prompts.
- **Non-Blocking Browser Streams (`Readable`, `Writable`, & `ByteBuffer`)**:
  - `WebFileSystemNativeImpl` bridges browser `File` / `Blob` / `ReadableStream` and `FileSystemWritableFileStream` directly to GenericUI's `Readable`, `Writable`, and `ByteBuffer` APIs (`read`, `write`, `openReadable`, `openWritable`, `openReadableFromFileDialog`, `openReadablesFromFileDialog`, `openWritableFromFileDialog`).
- **`ConfigDirectory` & `CacheDirectory` (`WebUserDirectoryNativeImpl` — Direct `window.indexedDB` Without `Database`)**:
  - On `:web`, `ConfigDirectory` (`scheme = "config"`) and `CacheDirectory` (`scheme = "cache"`) implement `IFileSystem` (`read`, `write`, `openReadable`, `openWritable`, `openDatabase`) and persist async binary `ByteBuffer` / `Readable` / `Writable` files **directly in browser `window.indexedDB`** inside the dedicated **`"genericui_user_dirs:<appName>"`** database (using the `"config"` and `"cache"` object stores) **without using the `Database` class**.

### 3. Native `Database` (`window.indexedDB` with Strictly Isolated `"genericui_db:..."` + `"tbl:..."` Namespaces)
- Backed directly by browser **`window.indexedDB`** (`IDBFactory`, `IDBDatabase`, `IDBTransaction`, `IDBObjectStore`, `IDBIndex`, and `IDBCursorWithValue`) in `WebDatabaseNativeImpl`.
- **Zero Namespace Collision with `ConfigDirectory` & `CacheDirectory`**:
  - While `ConfigDirectory` and `CacheDirectory` use `window.indexedDB` directly in `"genericui_user_dirs:<appName>"` (object stores `"config"` and `"cache"`), `Database` on `:web` opens its own IndexedDB database named **`"genericui_db:<databaseName>"`** (`"genericui_db:..."`) and prefixes every table's `IDBObjectStore` name with **`"tbl:<tableName>"`** (`"tbl:..."`).
  - Because both the IndexedDB database name (`"genericui_db:..."` vs. `"genericui_user_dirs:..."`) and the object store names (`"tbl:..."` vs. `"config"` / `"cache"`) are disjoint, `Database` on `:web` can **never conflict** with `"config"` or `"cache"` user directories, even if a user creates a `Database` table named `"config"` or `"cache"`.
- Evaluates structured `DatabaseTableSchema`, `DatabaseRecord`, `DatabaseQuery`, and `DatabaseFilter` ASTs asynchronously against IndexedDB object stores and secondary indexes with **zero string query parsing**, supporting `defineTable`, `putRecord`, `getRecord`, `query`, `count`, `deleteWhere`, and `ByteBuffer` / `Readable` / `Writable` binary streaming (`read`, `write`, `openReadable`, `openWritable`).

### 4. Async `Network` (`TcpClient`, `UdpClient`), `HttpClient`, `WebSocket` / `SocketIoClient`, & `IApplication.isOffline`
- **Raw TCP & UDP Capability Reporting (`Network.supportsTcp() == false`, `Network.supportsUdp() == false`)**:
  - Because web browsers disallow raw OS TCP and UDP sockets, `WebNativeFactory.supportsTcp()`, `WebNativeFactory.supportsUdp()`, `Network.supportsTcp()`, `Network.supportsUdp()`, `TcpClient.supports()`, and `UdpClient.supports()` all return **`false`** on `:web`.
- **Async `HttpClient` (`WebHttpClientNativeImpl`)**:
  - Backed by the browser `window.fetch()` API (`AbortController` timeouts, `Headers`, `Uint8Array` / `ByteBuffer` request bodies, and `Response.body` `ReadableStream` chunked `Readable` streaming via `openStream`).
- **Async `WebSocket` & `SocketIoClient` (`WebWebSocketNativeImpl`)**:
  - Backed by the browser `window.WebSocket` API (`binaryType = "arraybuffer"` for binary `ByteArray` / `ByteBuffer` frames and UTF-8 text frames), powering both raw `WebSocket` connections and the Engine.IO v4 / Socket.IO v4 `SocketIoClient` (`connect`, `emit`, `emitWithAck`, `on`, `once`, custom namespaces).
- **`IApplication.isOffline` Connectivity Monitoring (`WebNetworkMonitorImpl`)**:
  - Queries `window.navigator.onLine` and listens to browser `window.addEventListener("online", ...)` and `window.addEventListener("offline", ...)` events via `WebBrowserDomBridge` to update `app.isOffline` / `app.isOnline` in real time and notify listeners registered via `app.addOfflineListener(...)` and `app.setOnOfflineChanged(...)`.
