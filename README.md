# `:web` — Browser Backend (`jsMain` & `wasmJsMain` — Bootstrap 5 + DOM)

## Overview
`:web` is the browser backend for GenericUI, targeting both **Kotlin/JS** (`js(IR)`) and **Kotlin/Wasm** (`wasmJs`). It renders native HTML5 DOM elements styled with Bootstrap 5 (`bootstrap.min.css`, `bootstrap-icons.css`) and depends on `:common` and `:systemCommon`.

---

## Single-`commonMain` Architecture & `WebLauncher`

Consumer applications write their UI and `@MainAppFragment` / `@AppFragment` classes strictly in `src/commonMain/kotlin` and `src/commonMain/resources`. The GenericUI Gradle plugin (`GenericUiGenerateLaunchersTask`) automatically generates the `jsMain` and `wasmJsMain` entry point stubs calling `WebLauncher`:

```kotlin
// Auto-generated by GenericUiGenerateLaunchersTask in build/generated/genericui/launchers/{jsMain,wasmJsMain}
fun main() {
    WebLauncher.launch(
        title = "My App",
        width = 1280,
        height = 800,
        mainFragmentFactory = { MyMainFragment() }
    )
}
```

`WebLauncher` (`com.nexustools.genericui.web.WebLauncher`):
1. Calls `WebNativeBootstrap.ensureInstalled()` to register `WebWidgetFactoryProvider`, `WebSystemProvider`, `WebResourceResolverImpl`, `WebPreferenceStoreImpl`, `WebFragmentHistoryBridge`, and `WebAppFragmentLauncher`.
2. Mounts a root `FragmentHostFragment` inside the active `WebWindowImpl` (`#genericui-root` DOM viewport via `WebDomMountEngine`) and dismisses the generated splash screen (`window.__genericuiHideSplash()`).
3. Synchronizes top-level `@AppFragment` navigation and internal `FragmentHostFragment` navigation with browser URL `#hash` and `window.history.state`.

## Browser `#hash` & `window.history.state` Integration (`WebFragmentHistoryBridge`)

`WebFragmentHistoryBridge` (`com.nexustools.genericui.web.WebFragmentHistoryBridge`) implements `FragmentHistoryBridge` from `:common` (`com.nexustools.genericui.fragment.FragmentHistoryBridge`) and binds every `FragmentHostFragment` to the browser's native HTML5 History API:

1. **URL `#hash` Routing (`window.location.hash`)**:
   - Navigating to a fragment pushes or replaces the browser URL hash (`#<fragmentId>`, e.g. `#dashboard`, `#editor`, `#settings`) via `window.history.pushState(stateJson, "", "#$fragmentId")` or `window.history.replaceState(stateJson, "", "#$fragmentId")`.
   - Deep-linking directly to `https://example.com/#settings` reads `window.location.hash` via `WebFragmentHistoryBridge.currentHash()` and restores the matching fragment on initial load.
2. **Typed `FragmentBundle` Persistence in `window.history.state`**:
   - Both the navigation `args: FragmentBundle` and the fragment's saved state (`onSaveState(outState: FragmentBundle)`) are serialized to JSON using `PreferenceObjectCodec` and stored inside the browser history entry's native `window.history.state` payload (`{"fragmentId":"...","args":{...},"savedState":{...}}`).
3. **Browser Back / Forward Buttons (`popstate`)**:
   - Clicking the browser's native Back or Forward buttons fires `window.onpopstate`. `WebFragmentHistoryBridge` decodes the JSON `window.history.state` entry back into `FragmentHistoryState(fragmentId, args, savedState)` and dispatches it to `FragmentHostFragment`, which restores the fragment and invokes `onRestoreState(savedState)`.

## Web `TitleCapabilities` & 4-State Navbar / MenuBar Chrome Rules

On `:web`, the browser tab already provides the OS-level window frame, so `WebWindowImpl` reports:

```kotlin
TitleCapabilities(
    isTitleBarRequired = false,
    isEmulated = true,
    supportsIcon = true,
    supportsLeadingComponents = true,
    supportsCenterComponents = true,
    supportsTrailingComponents = true,
    supportsCustomComponents = true,
    supportsSubtitle = true,
    supportsMinimizeButton = false,
    supportsMaximizeButton = false,
    supportsCloseButton = false,
    supportsFullscreenButton = true,
    canEmbedComponentsInTitleBar = true,
    titleBarRendersAsNavbar = true,
    menuBarRendersAsNavbar = false,
    menuBarMergesIntoTitleNavbar = true
)
```

`WebWindowImpl` and `WebDomMountEngine` enforce the **4-state Web chrome rule**:
1. **Neither `TitleBar` nor `MenuBar` set**: **No top chrome is rendered at all**; the root container fills the entire browser viewport (`100vw x 100vh`).
2. **`MenuBar` only (no `TitleBar`)**: Renders **only** a horizontal Bootstrap menu bar (`<nav class="genericui-menubar">` with dropdown menus) at the top of the viewport.
3. **`TitleBar` only (no `MenuBar`)**: Renders a Bootstrap `<nav class="navbar navbar-expand ...">` (`WebNavbarImpl`) containing the brand icon, title, subtitle, leading components, center components, and trailing components. Custom components attached to `TitleBar` are marked `mountedInTitleBar = true` so `WebDomMountEngine` mounts them strictly once inside the navbar and excludes them from the window body.
4. **Both `TitleBar` and `MenuBar` set**: Merges both into a **single** Bootstrap `<nav class="navbar">` (`menuBarMergesIntoTitleNavbar = true`):
   - **Left / Center**: Brand icon, title, subtitle, leading components, and center components.
   - **Right**: `MenuBar` top-level dropdown items followed by trailing components.

## Web Asset URL Resources (`WebResourceResolverImpl`)

During the Gradle build, `GenericUiCompileResourcesTask` packages `src/commonMain/resources/` into the web distribution's `assets/` directory (`assets/drawable/`, `assets/raw/`, `assets/font/`, etc.) alongside compiled string, color, dimension, and theme tables.

At runtime, `WebResourceResolverImpl` (`com.nexustools.genericui.web.system.WebResourceResolverImpl`) resolves:
- Resource URLs (`resolveUri(resId)`) to relative browser asset paths: `"assets/${resId.type.directoryName}/$fileName"`.
- Localized strings, colors, dimensions, themes, and binary byte arrays from the registered asset bundles.
